**ส่วนลดทบต้นกันเหมือน Agoda** — พิสูจน์ได้จากตัวเลขจริง:

```
1,800 × (1 − 0.16) × (1 − 0.10) = 1,360.80
```

Genius Potential Score: **47/100**

### หลักคิด — ให้ราคาลูกค้าจ่ายเท่ากับ Agoda

ใช้เคสมาตรฐานเดียวกับ `agoda_improve.md`: **ลูกค้าไทย จองผ่านมือถือ**
ฝั่ง Booking เคสนี้คือ **สมาชิก Genius ที่จองบนมือถือ**

```
Booking:  Genius 10% × Mobile 10%      = ลด 19%  → ชั้นวาง = เป้า ÷ 0.81
Agoda:    Occupancy 10% × Mobile 10%   = ลด 19%  → ชั้นวาง = เป้า ÷ 0.81
```

**ตัวเลขออกมาเท่ากันพอดี** → ใช้ราคาชั้นวางชุดเดียวกันได้ทั้งสองเจ้า
ลูกค้าจ่ายเท่ากัน = **rate parity ปลอดภัย** และดูแลตารางเดียวไม่ต้องกลัวหลุดคนละทาง

คืน blackout ก็ตรงกันอีก:

```
Booking:  พัก Genius ไว้ เหลือ Mobile ชั้นเดียว  → ชั้นวาง = เป้า ÷ 0.90
Agoda:    Occupancy ไม่ทำงาน เหลือ Mobile        → ชั้นวาง = เป้า ÷ 0.90
```

> ⚠️ **ต้องสร้าง Mobile rate 10% ก่อน** ถึงจะใช้สูตรนี้ได้

## 8. ต้องกลับมาดูเมื่อไหร่

**16 ก.ย. 69 (2 สัปดาห์หลังแก้)** — รอบตรวจผลรอบแรก ดู 3 ตัวเลขนี้:

| ตัวชี้วัด | ก่อนแก้ | คาดหวัง |
|---|---|---|
| ADR ที่ได้จริง | THB 1,352.70 | **สูงขึ้น** — ราคาคืนอีเวนต์ขึ้นเยอะ คืนเงียบลดลง |
| CTR (เห็น → คลิก) | 1.73% | **สูงขึ้น** — content 100% + ราคาคืนเงียบถูกลง + ป้าย mobile rate |
| Availability for search | 32.46% | **ลดลงเหลือ ~28%** ← คาดไว้แล้ว เพราะปิด 16–31 ธ.ค. |

⚠️ อย่าตกใจถ้า **views ลดลง** — เป็นผลโดยตรงจากเพดาน 15 ธ.ค. ไม่ใช่ความผิดพลาดของการแก้ราคา
ตัวที่ต้องดูจริง ๆ คือ **ADR และ CTR** ซึ่งไม่ขึ้นกับจำนวนคืนที่เปิด
